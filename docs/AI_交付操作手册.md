# AI 交付操作手册

本手册定义 Gemini 网页端、Antigravity 和 ChatGPT 在 WinDevice-Inspector 仓库中的实际交接。总入口见 [AI_AGENT_GUIDE.md](../AI_AGENT_GUIDE.md)，完整交付状态管理见 [交付中心](../DELIVERY/README.md)。

## 一、固定分工

| 角色 | 主要职责 | 禁止事项 |
|---|---|---|
| Gemini 网页端 | 需求分析、技术调研、方案比较、编写/修订正式任务书和返修任务书 | 不假设自己拥有本地工作区、终端或 Git 写权限；不与 Antigravity 并行修改同一工作区 |
| Antigravity + Gemini 4 Hydrogen Extra High | 按任务书独立开发、修改文件、运行可用测试、生成完整 ZIP/回执/哈希；具备权限时创建分支、提交和推送 | 不扩大范围；不自行更换模型；不推送 main、不强推、不合并 PR、不自我验收 |
| ChatGPT GPT-6 | 独立审查、返修意见、审查记录、交付归档和索引维护 | 未经负责人明确触发不自动审查或推进 |
| 项目负责人 | 审核任务书、授权执行、核对交付、触发审查、最终验收 | 最终验收权不可委托给 AI |

## 二、固定文件流

1. Gemini 网页端阅读 AI_AGENT_GUIDE.md、任务中心和相关资料，编写自包含任务书。
2. 项目负责人审核并明确授权。
3. Antigravity 选择 Gemini 4 Hydrogen Extra High，读取总规范、工作流规范和任务书。
4. Antigravity 先完成 [能力核验清单](工作流/能力核验清单.md)，确认仓库、模型、终端、Git、测试和 ZIP 能力。
5. Antigravity 独立实施任务书允许的内容，执行真实可用的测试。
6. Antigravity 生成一个完整 ZIP、文件清单、完成回执、测试证据和 ZIP SHA-256。
7. 若有远端 Git 写权限，Antigravity 从最新 main 创建任务轮次专属分支，提交到 DELIVERY/INBOX/待交付/ 并推送；无权限时停止并报告，不得声称已提交。
8. 项目负责人核对分支/提交或本地 ZIP，明确通知 ChatGPT 开始审查。
9. ChatGPT 独立审查准确的分支、提交和完整文件；需返修时出具报告，由 Gemini 网页端制作下一轮返修任务书。
10. 审查收尾时 ChatGPT 按交付中心规则归档原始交付和报告、更新任务索引/审查索引/归档索引，并清理已处理的收件箱内容，保留 README。
11. 项目负责人明确作出最终验收决定。

## 三、本地暂存区

- DELIVERY/LOCAL_STAGING/待上传/ 是本地中转目录，Git 忽略，不是远端仓库交付入口。
- 用户可将 Gemini 生成的 ZIP 放入暂存目录；Antigravity 负责检查、解压和整理。
- 解压前检查 ZIP 路径穿越、绝对路径、重复文件、超出任务范围的文件、可疑二进制和敏感信息。
- 不得将暂存目录全部内容不加区分地复制进仓库。
- 不得提交密钥、令牌、浏览器数据、个人文件、真实设备扫描数据或本机隐私信息。
- 不得静默删除唯一副本；先确认远端分支/归档副本可读取。

## 四、Git 分支与提交

- 每个任务/轮次使用独立分支，例如 delivery/WDI-DIAG-001-R2。
- 分支从执行时最新 main 创建；任务书基准 SHA 仍用于内容审查。若 main 变化影响本轮文件，先比较并报告。
- 不直接推送 main，不强制推送，不重写历史，不自行合并 PR。
- 同轮重复上传不得覆盖已提交原件；返修使用新轮次/新分支。
- INBOX/待交付/ 保持平面入口，保留原始文件名和 ZIP 内必要目录结构。
- 推送后核验远端分支 HEAD 与回执 commit SHA 一致。
- 若当前 Antigravity 环境无法创建分支、提交或推送，标记不可用，输出完整 ZIP 和人工操作步骤，等待负责人决定。

## 五、开工前检查

1. 确认仓库根目录、仓库名和当前分支。
2. 阅读 AI_AGENT_GUIDE.md、工作流规范、任务中心当前指针和本轮任务书。
3. 确认任务 ID、轮次、基线 SHA、允许文件范围和停止门禁。
4. 核验 Gemini 4 Hydrogen Extra High 是否可用，不可用时不得静默换模型。
5. 列出所有输入文件；ZIP 先列目录再安全解压。
6. 检查冲突、超范围文件、敏感信息和空文件。
7. 记录输入文件、输出文件、大小和 SHA-256（可用时）。
8. 完成后核验 Git diff、提交内容、远端分支和 commit SHA。

## 六、完成回执

必须包含任务 ID/轮次、实际模型、基线 SHA、分支和 commit SHA（如有）、ZIP SHA-256、文件清单、执行命令和退出码、测试真实结果、未执行项目及原因、偏离任务书事项、风险和已知限制。未执行测试写 Not run。

## 七、人工触发与验收门禁

Antigravity 推送不自动触发 ChatGPT。负责人需明确说“某任务某轮已交付，请审查”。ChatGPT 核对准确分支和 SHA 后才开始审查。分支推送、审查通过、本机验证通过、负责人验收和任务关闭是不同状态。

## 八、绝对禁止

- 直接向 main 推送未经审查的开发交付。
- 强制推送、删除远端分支、覆盖历史交付或擅自合并 PR。
- 将真实扫描数据、凭据、个人文件或浏览器配置上传。
- 将未执行测试写成通过。
- 在负责人尚未明确触发时自动进入下一阶段。
