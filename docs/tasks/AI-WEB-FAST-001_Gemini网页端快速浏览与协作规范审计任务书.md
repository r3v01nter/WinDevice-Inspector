## 2. 为什么建立本任务

项目负责人发现，Gemini 网页端通过远程浏览器逐页访问 GitHub 仓库比较慢。反复读取目录、重复打开说明文件、在多个文档之间来回跳转，会消耗时间和上下文。

本任务希望把项目背景、角色分工、任务状态、交付规则和审计目标集中在一份自包含的任务书中，让 Gemini：

1. 先通过本任务书获得大部分必要上下文；
2. 只打开少量权威文件核对当前规则；
3. 不做无目的的全仓库浏览；
4. 基于自己实际能用的网页浏览、文件读取、分析和输出能力，评估现有流程；
5. 最后向项目负责人提出如何进一步减少浏览成本、提高协作效率的建议。

这里的“加速”主要指减少不必要的页面访问、重复读取和上下文切换，不承诺改变 GitHub 或浏览器自身的网络加载速度。

## 3. 项目背景快照（优先使用，不必重新搜索）

### 3.1 项目目标

仓库名称：WinDevice-Inspector。

这是一个 Windows 原生设备诊断与 AI 就绪报告工具项目，目标技术栈为 C# / .NET 10 LTS / WPF，初始目标环境为 Windows 11 x64。

产品方向包括：
- 枚举 Windows 可识别的硬件、PnP 设备、驱动、USB/PCI/网络/音频等接口；
- 收集系统可靠性证据，例如意外关机、蓝屏、WHEA、Kernel-Power 等；
- 区分采集状态与诊断结论，不能把采集失败或未知误判为正常；
- 用户手动启动扫描，每次扫描前明确确认；
- 本地保存扫描历史；
- 生成 JSON、XLSX、HTML 和 AI 分析说明组成的报告 ZIP；
- 默认不自动上传、不自动连接 AI 服务、不自动修复、不修改驱动或系统设置。
