## 3. 必须完成的修订内容

### R2-01｜全量 PnP 设备架构

定义通用设备枚举和逐设备数据结构，覆盖 Windows 当前可枚举设备，而非固定九类。说明当前设备、隐藏设备、历史断开设备、虚拟设备如何分类及避免重复/误报；定义设备 ID、实例路径、硬件 ID、父子关系、Problem Code、驱动信息等字段的落位。

### R2-02｜采集状态与诊断结论双轴

明确分离 Collection Status 与 Diagnostic Finding，分别定义枚举、适用层级、映射规则和示例。读取成功不代表设备健康正常；Unsupported、Unavailable、PermissionDenied、Failed、Skipped 不得被误写成 Normal；数据可疑应有独立警告/有效性表达。

### R2-03｜完整 Schema 与演进策略

说明 Schema 如何表达设备、驱动、接口/总线、传感器、存储健康、系统事件、采集缺口、原始证据引用和完整性统计。提供至少一个纯合成数据示例（可以是 JSON 片段），说明版本兼容与未来扩展机制。不得使用真实机器标识或个人数据。

### R2-04｜采集器与 Diagnostics 边界

给出可独立测试的采集器职责：PnP/设备状态、驱动、硬件库存、传感器/健康、接口/总线、系统可靠性事件。明确只读采集、权限降级、PowerShell 7/5.1 兼容性和不支持/失败回报方式。Diagnostics 负责事件规范化和证据关联，不得启动扫描。

### R2-05｜Reporting 与报告包

明确 JSON、XLSX、HTML、AI 分析说明、ZIP 的模块边界、依赖方向和数据流。XLSX 至少规划：诊断总览、全部当前设备、异常设备、警告设备、隐藏/历史设备、驱动、接口、传感器、系统事件、采集失败/无法检测、采集完整性等工作表。每个当前设备一行；复杂原始字段可通过稳定 ID/JSON 附件关联，不得静默丢弃。

对 XLSX/ZIP 库给出候选项和取舍（许可、维护、体积、兼容性、测试），本轮只提出建议，不擅自新增生产依赖。

### R2-06｜隐私与导出门禁

定义统一报告包导出前提示和取消门禁。用户取消时不得打开保存对话框或写文件。明确原始证据报告与可选脱敏分享副本必须区分，不能静默删改原始数据。

### R2-07｜采集完整性与测试矩阵

定义设备枚举数量、逐类采集成功/失败/不支持/权限不足/无效数据统计。补充 Phase 1 必测与后续阶段测试映射，包括 PnP 合成数据、重复/父子设备、Problem Code、传感器离群数据、SMART/NVMe 能力差异、事件时间线、Schema 兼容、XLSX/HTML/ZIP 完整性及隐私取消门禁。

### R2-08｜C-02 与解决方案位置

保留 Persistence 独立项目/并入 Core 的方案对比，说明完整产品目标对边界的影响；同时比较 `src/WinDeviceInspector.sln` 与仓库根目录 `WinDeviceInspector.sln`。不要替项目负责人作最终批准。
