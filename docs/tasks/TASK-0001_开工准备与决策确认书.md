## 1. 项目背景

WinDevice Inspector 是面向 Windows 用户的本地优先设备与系统证据采集工具。产品收集硬件、设备、驱动、Windows 配置和可靠性信息，保存本地扫描历史，并帮助用户生成可由本人审阅后分享给 AI 的诊断材料。

产品不是自动修复工具，不应擅自修改系统，也不连接 AI 服务自动上传数据。

### 已确认技术基线

- C# / .NET 10 LTS / WPF。
- 首发目标：Windows 11 x64。
- PowerShell 作为受控、只读的独立子进程采集后端。
- 扫描历史保存在当前用户本地应用数据目录。
- 扫描和导出均由用户主动触发。
- 便携版与安装版均属于 V1 目标，但打包方案与数据路径策略可在后续阶段定型。

### 不可违反的产品约束

1. 应用启动、打开首页、读取历史记录时不得启动系统采集。
2. 每次采集都必须由用户主动发起，并在采集开始前展示范围、目的、敏感信息类别和权限要求。
3. 用户取消确认时不得创建或启动采集子进程。
4. 采集只读，不自动提权，不安装/更新/禁用/删除驱动，不修复或调优系统。
5. 不进行遥测、自动上传、云同步或自动连接 AI 服务。
6. 不把真实机器扫描数据、个人路径、凭据或令牌提交到仓库。
7. 单一交付入口固定为 DELIVERY/INBOX/待交付/；Gemini 不直接提交仓库。
8. 不得把未执行的 build/test/runtime 检查写成通过。

## 3. TASK-0001 的目标范围

完成首个可运行垂直切片，打通以下链路：

1. WPF 应用启动，显示从未扫描的空状态；启动时不采集。
2. 用户主动点击 Start Quick Collection。
3. 应用展示采集范围、目的、可能涉及的敏感数据和权限要求。
4. 用户明确确认后才启动受控 PowerShell 子进程；取消则不启动。
5. 子进程执行只读采集，输出结构化、版本化 JSON。
6. 应用显示进度和各采集类别结果；单类失败不得丢弃其他成功结果。
7. 完成的扫描保存为本地历史记录。
8. 用户可打开历史记录，而不触发新扫描。
9. 用户可主动选择路径导出原始 JSON。

### 首轮采集类别

- Windows 版本、版本号、Build、架构、安装日期和最近启动时间。
- 计算机厂商、型号和系统类型。
- CPU 名称、核心数和逻辑处理器数。
- 主板厂商/产品、BIOS 厂商/版本/日期。
- 物理内存总量及系统可提供的内存模块信息。
- GPU 名称、驱动版本和驱动日期（可用时）。
- 物理磁盘、逻辑卷、容量、盘符、文件系统和可用空间。
- 网络适配器、状态、MAC、链路速度及 IP/DNS 配置（注意敏感信息）。
- 状态异常的 PnP 设备和问题代码。

首轮不做温度、功耗、风扇、实时利用率、跑分或压力测试。

## 5. 开工前口径确认

以下为建议方案，不是已批准决定。负责人确认前，不得把建议写入正式产品/架构决定，也不得开始受影响的实现。

### C-01｜JSON Schema：对齐架构必需字段

**现状：** 旧 TASK-0001 的结果契约列出 schemaVersion、scanId、collectedAtUtc、computerName、collectorVersion、categories；当前技术架构还要求 timeZoneId（或等价时区上下文）、applicationVersion、每类别 durationMs（可测量时）以及查询窗口/采集参数。

**建议：** 首个 Schema v1 纳入以下字段：
- 顶层：schemaVersion、scanId、collectedAtUtc、timeZoneId、computerName、applicationVersion、collectorVersion、categories。
- 类别级：稳定 id、name、status、source、collectedAtUtc、durationMs（可测量时）、data、warnings、query/collectionParameters（适用时）。
- 明确字段必填/可空规则；未知值不得伪造；单类失败不影响其他类别。
- 查询参数只记录实际使用的参数，不把敏感命令行或秘密写入结果。

**负责人选择：**
- [ ] A：按上述建议将这些字段纳入 Schema v1。
- [ ] B：首轮使用精简 Schema，明确记录版本迁移策略，并将扩展字段推迟到后续版本。
- [ ] 其他：负责人另行说明。

### C-02｜Phase 1 项目拆分：Persistence 是否独立

**现状：** ADR-0001 描述 App、Core、Collectors、Diagnostics、Reporting 五个逻辑项目；技术架构另列 Persistence，形成五/六项目表述差异。技术架构同时明确：不要为了匹配图示而创建所有项目，首个垂直切片应采用最小且连贯的结构。

**建议：** TASK-0001 先按最小可测试结构实施；Persistence 先作为独立模块/命名空间，是否单独建立 csproj 由实际依赖边界和测试价值决定。不得仅为凑齐六项目而拆分，也不得因此破坏 Core 与 WPF 的依赖方向。

**负责人选择：**
- [ ] A：Phase 1 单独建立 Persistence 项目。
- [ ] B：Phase 1 将 Persistence 保留为独立模块/目录，暂不单独建项目；后续有需要再拆。
- [ ] C：先由 Gemini 提交最小方案和依赖图，负责人再批准。

### C-03｜PowerShell 5.1 / 7 支持范围

**现状：** 技术架构要求优先 PowerShell 7，仅在兼容性经过测试时支持 Windows PowerShell；旧任务书则要求优先 pwsh.exe，缺失时回退 powershell.exe。当前没有真实的双版本集成测试证据。

**建议：** 首轮将 PowerShell 7 作为首选路径；保留 Windows PowerShell 5.1 回退路径，但只有完成两种环境的测试矩阵后才宣称双版本支持。若任一版本不兼容，应用必须明确提示并记录受限状态，不得静默切换后声称兼容。两种版本都应验证 JSON 编码、CIM/命令可用性、退出码、stderr/stdout、取消和超时。

**负责人选择：**
- [ ] A：支持 PowerShell 7 与 Windows PowerShell 5.1，必须双版本测试。
- [ ] B：首轮只正式支持 PowerShell 7；5.1 不可用时明确提示，不回退。
- [ ] C：首轮只支持系统自带 Windows PowerShell 5.1；PowerShell 7 延后。
- [ ] 其他：负责人另行说明。

### D-07｜原始 JSON 导出敏感信息提示

**现状：** 原始扫描 JSON 可能包含计算机名、序列号、MAC/IP、用户名、路径或设备元数据。产品要求用户主动导出；尚未明确是否在保存对话框前增加独立风险提示。

**建议：** 用户点击导出后，先显示一次简短提示，说明文件可能包含设备标识和网络信息；用户继续后再打开保存对话框。不得自动上传、自动分享或擅自删改用户要导出的原始证据。

**负责人选择：**
- [ ] A：增加导出前敏感信息提示。
- [ ] B：不增加额外提示，只保留明确的用户主动导出动作。
- [ ] C：其他：负责人另行说明。
