# 任务中心

这里是 WinDevice Inspector 的项目协作总入口。项目负责人日常查看任务、下载任务书、检查交付状态时，优先从本目录进入。

## 从这里开始

1. [当前任务](当前任务.md)：全仓库唯一的当前处理项指针。
2. [任务索引](任务索引.md)：所有任务的状态、任务书、交付包和审查记录。
3. [审查索引](审查索引.md)：每轮独立审查结论与本机验证状态。
4. [开发变更记录](开发变更记录.md)：只记录已实际合入并有证据的正式变更。

## 常用入口

- [任务书目录](../tasks/)：任务目标、范围、约束和验收标准。
- [交付入口](../../DELIVERY/INBOX/待交付/)：用户核查 Gemini 文件后，放入完整交付包。
- [交付归档](../../DELIVERY/ARCHIVE/)：保留原始交付批次，不覆盖历史版本。
- [独立审查记录](../reviews/)：ChatGPT 的审查报告和用户本机验证记录。
- [缺陷记录](../issues/)：待修复问题、复现步骤和复验结果。
- [协作规则](../AI_COLLABORATION.md)：项目负责人、Gemini、ChatGPT 的职责边界。

## 三方协作分工

- **项目负责人**：决定产品方向和范围；检查 Gemini 交付内容；手动上传交付包；提供本机测试证据；拥有最终验收权。
- **Gemini**：读取公开仓库和任务书，负责主要实现或指定产出，提交完整文件和真实完成回执；不直接提交仓库。
- **ChatGPT**：制定任务书、提供技术指导、独立审查交付、提出返修要求、整理归档并维护任务索引；不得把未验证事项写成已完成。

## 任务状态

标准流程：

`待规划 → 待生产 → 生产中 → 待交付 → 审查中 → 返工中（如需） → 待本机验证（适用时） → 验收通过 → 已归档`

特殊状态：`已暂停`、`已取消`、`被其他任务替代`。

状态必须由可核验的文件、审查记录或测试证据支持。提交不等于验收；代码审查通过不等于本机验证通过；归档不等于验收。

## 命名约定

- 面向项目负责人的任务书、审查报告、索引和操作说明优先使用中文文件名。
- 新任务书建议命名为 `TASK-编号_中文任务名称.md`，保留稳定任务编号。
- 审查记录建议命名为 `REV-任务编号-R轮次_审查报告.md`。
- 程序源码、项目名、API、JSON 字段、命令、技术标识和既有稳定路径保留英文，不为了中文化而破坏工具兼容性。
- 已有英文任务书不强制重命名；索引提供中文说明和直接链接。

## 维护规则

- `当前任务.md` 始终只指向一个当前处理项；其他并行或后续任务在任务索引中标明。
- 任务索引和审查索引只追加或修正事实，不删除历史记录。
- 原始交付包按批次保留；返修版不得覆盖上一轮原件。
- 任何提案在项目负责人明确批准前，都不是正式产品决定。
- 更新任务状态时同步检查本目录索引、根 README、文档索引和交付说明中的入口链接。
