# 任务中心

这里是 WinDevice Inspector 的项目协作总入口。项目负责人日常查看当前任务、打开或下载独立任务书、检查任务推进状态时，优先从本目录进入。

## 从这里开始

1. [当前任务](当前任务.md)：全仓库唯一的当前处理项指针。
2. [当前正式任务书：TASK-0001](../tasks/TASK-0001_正式实现任务书.md)：当前可直接打开、保存并交付执行方的完整任务文件；当前仅授权阶段 A。
3. [任务索引](任务索引.md)：所有任务的状态、任务书、交付包和审查记录。
4. [任务创建与推进规范](任务创建与推进规范.md)：任务如何创建、写成独立任务书、推进、交付、审查、返工、验收和归档。
5. [审查索引](审查索引.md)：每轮独立审查结论与本机验证状态。
6. [开发变更记录](开发变更记录.md)：只记录已实际合入并有证据的正式变更。

## 三方分工

- **项目负责人**：确定产品方向和范围；打开/下载独立任务书并决定是否启动；检查 Gemini 交付；手动上传；提供本机验证证据；拥有最终验收权。
- **Gemini**：依据独立任务书完成当前获准阶段；只核验任务书指定的相关仓库资料；返回完整文件和真实完成回执；不直接提交仓库。
- **ChatGPT**：检查项目现状、编写独立任务书、技术指导、独立审查、返工管理、归档并维护索引；不得把未验证事项写成已完成。

## 状态流转

待规划 → 待开工决策 → 待生产 → 生产中 → 待交付 → 审查中 →（需返工时）返工中 → 待本机验证（适用时）→ 待负责人验收 → 验收通过 → 已关闭

具体进入条件、退出条件和特殊状态见[任务创建与推进规范](任务创建与推进规范.md)。

## 命名约定

- 面向项目负责人的任务书、审查报告、索引和操作说明优先使用中文文件名。
- 新任务书建议命名为 TASK-编号_中文任务名称.md，保留稳定任务编号。
- 审查记录建议命名为 REV-任务编号-R轮次_审查报告.md。
- 程序源码、项目名、API、JSON 字段、命令、技术标识和既有稳定路径保留英文。
- 已有英文任务书可保留作历史追溯；索引应明确标注其是否仍有效。

## 维护规则

- 当前任务.md 始终只指向一个当前处理项；其他并行或后续任务在任务索引中标明。
- 任务索引和审查索引记录真实状态，不删除历史记录。
- 原始交付包按任务编号和轮次保留；返修版不得覆盖上一轮原件。
- 任何提案在项目负责人明确批准前，都不是正式产品决定。
- 更新任务状态时同步检查任务中心、根 README、文档索引和交付说明中的入口链接。
